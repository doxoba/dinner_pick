# 🌙 저녁픽

배달 위주로 먹는 부부를 위한 **저녁 안주 추천** 웹앱. [한끼픽](https://github.com/doxoba/today_lunch)과 같은 구조(빌드 없는 정적 파일 + Cloudflare Worker/KV)와 디자인 언어를 쓴다.

두 사람이 각자 계정으로 **음식 월드컵**을 해서 취향을 만들고, 인원·인당 가격·카테고리·맛 키워드를 고르면 **두 사람의 교집합**에서 메뉴를 뽑아 **왜 그 메뉴인지**까지 설명해준다.

## 기능

| 기능 | 설명 |
|---|---|
| 계정 + 가구 | 아이디/비밀번호 가입. 한 사람이 가구를 만들면 초대 코드가 생기고, 배우자가 그 코드로 합류해 취향·기록·설정을 공유 |
| 음식 월드컵 | **96강**(메뉴 96개, 약 95경기). 대진이 안 맞는 자리는 부전승으로 올라가요. **"둘 다 싫어요"** = 비선호 지정, **"둘 다 좋아요"** = ♥ 표시(선호 그룹 하한 점수, 다음 라운드엔 한쪽만 랜덤으로 올라감). 선택마다 진행 상황이 저장돼 **이어서 하기**가 되고, **한 수 되돌리기**도 가능. 결과는 **선호 / 보통 / 비선호** 3그룹. 점수는 "통과한 라운드 ÷ 전체 라운드"(0~1)라 16강 같은 빠른 판과 섞어도 같은 척도. 마이페이지에서 언제든 다시 하기(기존 취향에 덧붙임) / 초기화 |
| 조건 | 인원 · 인당 가격대(술값 제외) · 카테고리 · **곁들일 술(멀티: 소주·맥주·막걸리·와인·하이볼·위스키·사케)** · 맛 키워드(#매운맛 #간장베이스 #된장베이스 #고추장베이스 …) · 조리 방식(구이·전·회·탕·튀김·볶음·찜·조림·무침·꼬치·마른안주·플래터·간식·면·빵) · 재료(고기·해산물·채소) |
| 안주 vs 식사 | 메뉴 DB는 **안주 중심**(158개). 밥류·국밥·식사 면은 **'식사'(마무리) 카테고리**로 분리돼서 평소엔 추천·월드컵에서 빠지고, 카테고리에서 '식사'를 고르면(안주와 함께도 가능) 후보가 돼요. 반주를 곁들이고 싶을 때 쓰는 용도 |
| 인당 가격 | 1인 메뉴는 가격 그대로, 나눠 먹는 메뉴(닭볶음탕 대 등)는 **총액 ÷ 인원**. 권장 인원 밖이면 후보에서 제외. 배달비는 제외(무료 요금제 전제) |
| 추천 | 하드 필터 → 두 사람 점수(평균 60% + 최저점 40%) → 가중 랜덤 3개. 한 명이라도 비선호면 제외. **"누구 취향으로?"** 에서 *둘의 교집합* / *한 사람에게 맞춰서*(상대가 싫어하는 메뉴도 나올 수 있음)를 고를 수 있고 선택은 기기에 기억 |
| 이유 설명 | 취향 · 최근 기록 · 가격/예산 · 키워드 일치 · 직전 식사와 다양성 · 권장 인원을 문장으로 |
| **같이 정하기(방)** | 4번째 탭 "같이". 한 명이 방을 열면(방장) 상대는 "참여하기" 한 번이면 입장(같은 가구라 코드 불필요, 6시간 뒤 자동 종료). 각자 **가격·카테고리·술·맛·조리·재료**를 고르고 **준비완료** → 모두 준비되면 **방장만** "메뉴 뽑기". 합치는 규칙: 술은 **합집합**(누가 고른 술이든 하나라도 어울리면 후보), 나머지는 **각자의 조건을 모두 만족**(교집합). 모두 준비하기 전에는 상대의 선택이 보이지 않고(눈치 방지), 준비완료 후엔 수정이 잠겨요. 방장이 "다시 뽑기"를 누르면 결과 카드 하단에 **"N번째 뽑는 중"** 이 **모두에게** 표시되고 지난 후보 목록도 볼 수 있어요(횟수는 서버가 셈). 상대는 **"다시 뽑자고 의견 내기"** 로 방장 화면에 요청을 띄울 수 있고, 방장이 "조건 다시 정하기"를 누르면 모두의 준비가 풀리며 횟수가 초기화돼요. 방 안에서도 "누구 취향으로"(교집합 / ○○님에게 맞춰서)를 방장이 정해요. 확정하면 기록에 저장되고 방이 닫혀요. 둘의 조건이 안 겹치면 "누구 조건만이면 몇 개"를 알려줘요 |
| 최근 N일 제외 | 기본 7일(설정 가능). 닭볶음탕 중/대처럼 같은 음식의 사이즈 변형도 같은 메뉴로 취급 |
| 먹은 기록 + 평가 | "이걸로 먹을래요" → 기록. 👍/😐/👎를 각자 남기면 취향 점수에 반영(비슷한 메뉴에도 번짐) |
| 근처 식당 | 메뉴 키워드로 집 주소 기준 반경 내 가게 검색(카카오) + 쿠팡이츠 검색 링크 |

## 구조

```
index.html / style.css / config.js     화면 (한끼픽 팝 디자인, 모바일 우선)
app.js                                  UI · 상호작용 · 카카오 SDK 연동
core.js                                 추천 로직 (필터·점수·가중 랜덤·이유 문장·월드컵) — DOM 의존 없음
menus.js                                메뉴 DB (안주 158개 + 식사 34개: 가격·권장 인원·맛/재료 태그·검색어)
worker/worker.mjs                       Cloudflare Worker: 가입/로그인(PBKDF2+세션) · 취향/기록/설정 저장 · "같이 정하기" 방 · 카카오 평점 프록시
dev/server.mjs                          로컬 개발 서버 (정적 + worker를 메모리 KV로 실행)
test/*.test.mjs                         코어 로직 · Worker API(가입/취향/기록/방) 테스트 (npm test)
```

추천 계산은 전부 브라우저에서 하고, Worker는 얇은 저장소 + 인증이다. KV는 쓰기 경쟁을 피하려고 **사람마다/기록마다 키를 분리**했다(한끼픽 팀 모드와 같은 원칙).

## 로컬 실행

```bash
npm run dev      # http://localhost:8000  (Cloudflare 없이 가입/로그인/저장까지 동작, 서버를 끄면 데이터는 사라짐)
npm test         # 코어 로직 + Worker API 테스트
```

로컬에서 카카오 지도(식당 검색·주소 변환)를 쓰려면 카카오 콘솔에 `http://localhost:8000`이 등록돼 있어야 한다.

## 배포

1. **Worker + KV**
   ```bash
   npx wrangler kv namespace create DP        # 출력된 id를 wrangler.toml에 입력 (wrangler 버전에 따라 `kv:namespace`일 수 있음)
   npx wrangler secret put SIGNUP_CODE        # 권장: 가입 코드. 공개 URL이라 아무나 가입하지 못하게 막아둔다
   npx wrangler deploy
   ```
   (한끼픽처럼 대시보드에서 `worker/worker.mjs`를 붙여넣고 KV 바인딩 이름을 `DP`로 해도 된다.)
2. `config.js`의 `API_BASE`를 배포된 Worker 주소로 바꾼다.
3. **프론트엔드**: GitHub Pages(`main` 브랜치 루트)로 올린다. `SIGNUP_CODE`를 설정했다면 가입 화면에서 입력.
4. **카카오**: `config.js`의 `KAKAO_JS_KEY`는 한끼픽과 같은 키다. 카카오 디벨로퍼스 콘솔 > Web 도메인에 저녁픽이 올라가는 **오리진**이 등록돼 있어야 한다(같은 `https://<계정>.github.io`라면 이미 등록돼 있을 가능성이 높지만 확인 필요).

## 데이터와 한계 — 확인되지 않은 부분 포함

- **배달앱 데이터는 가져오지 않는다.** 쿠팡이츠·배민·요기요·땡겨요에는 소비자용 공개 API가 없는 것으로 알고 있고(직접 확인하지는 않음), 크롤링은 약관·차단 위험이 있어 쓰지 않았다. 대신 *메뉴를 먼저 정하고* 쿠팡이츠 검색 링크로 넘기는 구조다.
  - 쿠팡이츠 검색 URL(`coupangeats.com/search?keyword=`)이 실제로 앱/웹 검색으로 이어지는지는 **미확인**. 안 되면 `app.js`의 `coupangUrl()`만 고치면 된다. 배민은 검색어 복사 버튼만 제공한다.
- **식당은 카카오 검색 결과**라서 쿠팡이츠에 입점했는지/배달 가능한지는 알 수 없다. 배달 전문점(클라우드 키친)은 카카오맵에 없거나 리뷰가 적을 수 있다.
- **식당 평점**은 카카오 비공식 place-api(panel3)에서 평점처럼 보이는 필드를 찾아 쓴다. **응답 필드를 확인하지 못했다**(개발 환경에서 외부 호출이 막혀 있었음). 못 찾으면 평점 없이 거리순으로 보여준다. 배포 후 `https://<worker>/api/place?placeId=<카카오 장소 id>&debug=1` (로그인 토큰 필요)로 실제 응답 구조를 보고 `worker.mjs`의 `SCORE_KEYS`를 맞추면 된다.
- **메뉴 가격**은 2026년 배달앱 기준 *대략값*(추정)이다. 마이페이지의 "가격 보정"(×0.9~1.5)으로 전체를 조정하고, 정확히 맞추려면 `menus.js`의 표를 직접 고친다.
- 카카오 키워드 검색 결과는 한 번에 15개이고 거리순이다(평점 정렬은 평점을 얻은 상위 8개에 한해 적용).
- 로그인 실패 제한(8회/15분)과 가입 코드는 있지만 IP 단위 제한은 없다. KV는 최종 일관성이라 같은 아이디로 동시에 가입하는 극단적인 경우는 막지 못한다.
- 비밀번호는 PBKDF2-SHA256(10만 회, Workers 상한)으로 해시해 저장하고, 응답에 해시/솔트는 포함되지 않는다. 비밀번호 찾기는 없다(분실 시 KV에서 계정 삭제 후 재가입).

## 앞으로 할 만한 것

집 주소 여러 곳 지원 · 메뉴 DB 편집 UI · 메뉴 사진 · 쿠팡이츠 주문내역 붙여넣기로 취향 시드 · 날씨/요일 반영 · 비밀번호 변경

## 같이 정하기(방) 구현 메모
- 방 상태는 KV `room:{가구코드}:meta`(방장만 씀)와 `room:{가구코드}:m:{uid}`(각자 자기 것만 씀)로 나눠 저장해서, 둘이 동시에 눌러도 서로 덮어쓰지 않아요(한끼픽 팀 모드와 같은 원칙).
- "준비완료"는 `readyRound == meta.round`일 때만 유효해요. 방장이 "조건 다시 정하기"로 round를 올리면 모두의 준비가 한 번에 풀려요.
- 뽑기 계산은 **방장 브라우저**에서 하고 결과(메뉴·인당가격·이유)만 서버에 저장해요. 그래서 방장이 조작할 수 있다는 약점은 있지만, 뽑은 횟수는 서버가 세고 모두에게 보여서(그리고 지난 후보 목록이 남아서) 눈에 띄어요. 서버에서 뽑게 하려면 Worker에 메뉴 DB와 `core.js`를 넣어야 해요.
- 화면은 같이 탭이 열려 있으면 4초마다, 다른 탭이면 약 30초마다 방 상태를 확인해요(Cloudflare KV 무료 읽기 한도 절약). KV는 최종 일관성이라 드물게 반영이 늦을 수 있어요.
- **Worker 코드가 바뀌었으므로 배포 후 Cloudflare Worker에 `worker/worker.mjs`를 다시 붙여넣고 Deploy해야 해요.** KV 데이터는 그대로 유지돼요.
